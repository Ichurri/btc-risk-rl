## Puerta antes de crear una unidad

1. Confirmar `git status`, rama, commit y código `code_sha256()` igual a
   `abbf656fe24b78bb2197640761acc9cdcfef17596416a57de7a75b5261b11605`;
   registro SHA-256
   `43506140c41c349731fd0a5b4a6133b6cec6e9bf091c995ab65c1ed68260cc75`.
   La eliminación local previa de `.python-version` no se incorpora.
2. Exigir CA (`ADP1/online=1`), batería ≥50 %, `MemAvailable ≥4 GiB`, disco
   libre ≥20 GiB, `Linger=yes`, gestor `systemd --user=running`, ninguna otra
   unidad/campaña activa, raíz nueva o ledger `ready` sin `pending`, fuente
   de entrenamiento y huellas conformes. Un preflight `blocked` no permite
   iniciar mercado. La captura del 06/11 a las 17:24 fue `blocked` por CA
   desconectada y no sirve para lanzar.
3. La **primera comprobación formal de campaña** debe ejecutarse dentro de
   `BudgetAttempt`, que escribe antes el intento durable. `--prepare` carga
   suite completa, Ruff, preflight vigilado y comprobación del corte 2022
   a la fecha local. `--run` exige esas cuatro comprobaciones exitosas y
   recientes del mismo día. Un fallo de recursos previo a unidad permite
   reexamen en un día admisible; un fallo durante unidad deja `failed`.

## Servicio nocturno previsto

Iniciar **a partir de las 01:00** de una fecha admisible en
`America/La_Paz`; la sesión debe cerrar antes de las 09:00. La ventana
01:00–09:00 no
amplía las tres horas globales ni los dos días del estudio. El supervisor
detiene antes de iniciar una unidad si no caben su cota, checkpoint y reserva
antes de las 09:00.

Con puertas conformes y fecha vigente, el comando es:

```bash
systemd-run --user \
  --unit=oos-wf-cost-2022-01-session-01 \
  --property=Restart=no \
  /usr/bin/systemd-inhibit --what=sleep:idle --mode=block \
  --why='WF 2022: conservar supervisor despierto' \
  /usr/bin/bash -c 'cd /home/ichurri/Desktop/personal_projects/btc-risk-rl && /home/ichurri/.local/bin/uv run --frozen python scripts/run_oos_wf_cost_2022.py --prepare && /home/ichurri/.local/bin/uv run --frozen python scripts/run_oos_wf_cost_2022.py --run'
```

No hay `Restart=on-failure` ni repetición automática. La prueba sintética
del 06/11 observó un inhibidor `sleep:idle` activo en una unidad de usuario
y su cierre `Result=success`; **no probó físicamente la pantalla apagada**.
No cerrar la tapa si el firmware apaga el host pese al inhibidor. El monitor
puede apagarse sin detener el gestor de usuario; conservar CA conectada.

## Auditoría y reingreso

```bash
systemctl --user show oos-wf-cost-2022-01-session-01.service \
  -p Result -p ExecMainStatus -p ActiveState -p InvocationID -p Restart
journalctl --user -u oos-wf-cost-2022-01-session-01.service --no-pager
sha256sum artifacts/oos-v12-wf-cost-only-2022-01/ledger.jsonl
```

Se auditan `artifacts/shared-pilot-budget/wf-2022-only-01-attempts.jsonl`,
la bitácora de comprobaciones, `sessions.jsonl`, `supervisor.jsonl`, cada
reporte y checkpoint, sus huellas, tiempos de Q/A/B+D y D, recursos y cargos
por fecha sin doble conteo. Un ledger `ready` con `pending=null` y último
checkpoint completo puede continuar **solo** después de `--prepare` nuevo
en día admisible, con nombre de servicio nuevo y saldo; jamás se repite una
unidad aceptada. Un ledger `failed` no se reanuda aunque conserve un
checkpoint anterior. Dos días activos agotados sin 11 unidades dan cierre
metodológico `incomplete`, sin aumentar los límites.

Tras `completed`, `failed` o `incomplete` se cierra prospectivamente el
gate de esta raíz en un commit propio, preservando aprobación y artefactos.
La medición solo informa costos de una C10 del corte 2022; no es evaluación
financiera ni permiso para abrir validación 2023 o prueba final.
